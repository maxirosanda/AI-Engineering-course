El problema

En IA, el tiempo se gasta esperando

Tu programa casi no "calcula": el cálculo ocurre en los servidores de OpenAI o Anthropic. Lo que hace tu programa es esperar.

Esperarque el prompt llegue
→
Esperarque el modelo procese
→
Esperarque los tokens vuelvan por la red

📜 Script lineal

Llama a un LLM y se queda quieto hasta que responde. Sirve para una prueba; no para un producto.

🏗️ Sistema de IA

Atiende cientos de usuarios, maneja varios flujos a la vez y muestra la respuesta mientras se escribe.

La arquitectura asíncrona convierte esa espera pasiva en una oportunidad para hacer otra cosa.

Un agente con tres pasos

Tu agente tiene que: 1) buscar en una base vectorial, 2) consultar una API de clima y 3) generar la respuesta con un LLM. Cada llamada tarda 2 segundos.

síncrono (bloqueante)
Base vectorial2 s
→
Clima2 s
→
LLM2 s

Una después de la otra: 6 segundos. Y mientras espera, el servidor no atiende a nadie más.

asíncrono
Base vectorial2 s
Clima2 s
→
LLM2 s

Las dos búsquedas esperan a la vez: 4 segundos. Y durante las esperas, el servidor atiende a otros usuarios.

El LLM necesita los resultados de las búsquedas, así que va después. Lo que no depende entre sí se puede esperar al mismo tiempo.

Concepto clave

Concurrencia cooperativa (no paralelismo)

👥 Paralelismo

Varios procesadores trabajando al mismo tiempo. Como tener tres cocineros.

lo que hace asyncio

🔄 Concurrencia cooperativa

Un solo cocinero que no se queda mirando el horno: mientras la tarea A espera datos de la red, cede el control para que avance la tarea B.

PalabraQué significa
I/OEntrada/salida: todo lo que implica esperar a algo externo (red, base de datos, disco, una API).
bloqueanteCódigo que frena todo el programa hasta terminar.
cooperativaCada tarea avisa cuándo va a esperar (con await) y deja pasar a otra.

Python 3.12 refina asyncio: mejora el rendimiento y elimina comportamientos viejos y ambiguos (como crear el loop automáticamente), para empujar patrones más limpios y predecibles.

Pilar 1

Corrutinas: async def y await

Una corrutina es una función que puede pausarse y retomar después.

📖 Una receta con señaladores

Empezás a cocinar. Llegás a "esperar a que el horno caliente" (await), dejás un señalador ahí y, mientras tanto, picás verduras para otra receta. Cuando el horno está listo, volvés al señalador.

async def fetch_llm_response(prompt: str):
    # La ejecución se pausa acá y libera el programa para otras tareas
    response = await client.chat.completions.create(model="gpt-4o", messages=[...])
    return response
  • async def declara que la función puede pausarse.
  • await marca el punto de espera: "acá voy a tardar, que siga otro". Solo se puede usar dentro de un async def.

🧑‍🍳 El mozo

Es uno solo (un solo hilo). Pero nunca se queda parado al lado de la cocina esperando un plato.

📋 El encargado

Lleva la lista de qué mesa espera qué cosa, y manda al mozo adonde haya algo para hacer.

No lo programás vos: lo crea y lo cierra asyncio.run(). Tu trabajo es no trabarlo (lo vemos en los anti-patrones).

Pilar 3

Tasks: tareas en segundo plano

Una task es una corrutina que ya fue programada en el event loop para ejecutarse "lo antes posible".

ObjetoCuándo se ejecutaAnalogía
corrutinaRecién cuando le hacés await. Sola, no hace nada.Una receta escrita
taskArranca en segundo plano mientras vos seguís con otra cosa.Un pedido ya entregado a la cocina
async def main():
    # create_task programa la corrutina: empieza a correr en segundo plano
    tarea = asyncio.create_task(buscar_documentos("envíos"))

    print("Mientras tanto, sigo con otra cosa...")

    resultado = await tarea    # cuando lo necesito, espero el resultado

Error típico: llamar buscar_documentos("envíos") sin await ni create_task. No se ejecuta nada, y Python avisa con coroutine was never awaited.

Patrones

El punto de entrada: asyncio.run()

Es la forma estándar de arrancar una aplicación asíncrona. Crea el event loop, espera a que terminen las tareas y cierra todo de forma limpia.

import asyncio

async def main():
    print("Iniciando sistema de IA...")
    # Lógica de la aplicación acá

if __name__ == "__main__":
    asyncio.run(main())   # un solo punto de entrada para todo el programa
hacé esto

Un único asyncio.run(main()) por programa. Todo lo demás se llama con await desde adentro.

evitá esto

Usar asyncio.get_event_loop() para arrancar. Si necesitás el loop desde adentro de una función async, usá asyncio.get_running_loop().

Varias llamadas a la vez: asyncio.gather

El patrón más común: disparar varias llamadas juntas y esperar a todas. Por ejemplo, comparar tres modelos con el mismo prompt.

async def compare_models(prompt):
    # Las tres llamadas esperan al mismo tiempo
    results = await asyncio.gather(
        call_openai(prompt),
        call_anthropic(prompt),
        call_local_llama(prompt),
        return_exceptions=True,   # clave: un fallo no tumba a los demás
    )
    return results   # lista en el MISMO orden en que pasaste las llamadas
  • Tarda lo que tarda la más lenta, no la suma de las tres.
  • Con return_exceptions=True, si una falla, su error vuelve como un resultado más de la lista.

Caso real: en un sistema RAG, buscar en la base vectorial y en una API de búsqueda web a la vez. No hay razón para esperar a una para empezar la otra.

Producción

Timeouts: el seguro contra la espera infinita

Los modelos pueden ponerse lentos y las APIs pueden fallar. Nunca dejes una llamada abierta indefinidamente.

try:
    async with asyncio.timeout(10.0):       # como máximo, 10 segundos
        response = await call_llm(prompt)
except TimeoutError:
    print("El modelo tardó demasiado. Aplicando estrategia de fallback...")

⏱️ Qué hace

Si lo de adentro del bloque supera el tiempo, lo cancela y lanza TimeoutError.

🔁 Qué hacer después

Un fallback (plan B): reintentar, usar otro modelo o devolver un mensaje claro al usuario.

asyncio.timeout() existe desde Python 3.11 y es la forma estándar en 3.12.

Semáforos: controlar cuántas a la vez

Si disparás 1.000 llamadas en un segundo con gather, la API responde 429: Too Many Requests. Un semáforo limita cuántas tareas pueden estar activas al mismo tiempo.

sem = asyncio.Semaphore(5)   # solo 5 llamadas a la vez

async def throttled_call(prompt):
    async with sem:           # si ya hay 5 adentro, espera su turno acá
        return await call_llm(prompt)

🚪 Como el portero de un local

Entran 5. El resto hace fila afuera, y cada vez que sale uno, entra otro.

📉 Rate limit

El límite de pedidos por minuto que te da cada proveedor. Si lo pasás, te rechaza las llamadas.

Podés crear las 1.000 tareas igual: quedan encoladas, y el semáforo asegura que solo corran 5 en simultáneo.

Anti-patrones

Mito: "async hace todo más rápido"

Falso. asyncio no acelera los cálculos: aprovecha las esperas.

I/O-bound: asyncio ayuda

El tiempo se va en esperar: llamadas a APIs, bases de datos, red.

→ asyncio

CPU-bound: asyncio no ayuda

El tiempo se va en calcular: limpiar datos pesados con Pandas, correr un modelo de PyTorch en tu CPU.

→ multiprocessing

Volviendo a la cocina: un solo cocinero puede vigilar diez hornos a la vez (esperas), pero no puede picar diez cebollas a la vez (trabajo).

El error más peligroso: bloquear el loop

Si dentro de una función async llamás a algo síncrono que tarda, frenás a todos tus usuarios. El encargado se queda congelado, y nadie más recibe su comida.

bloquea todo 
async def procesar():
    time.sleep(5)   # nadie avanza por 5 s
cede el control 
async def procesar():
    await asyncio.sleep(5)   # los demás siguen

¿Y si la librería no tiene versión async? Mandala a un hilo aparte con asyncio.to_thread():

# Corre la función síncrona en otro hilo, sin bloquear el loop principal
result = await asyncio.to_thread(blocking_sync_function, data)

El caso típico en IA: usar el cliente síncrono (OpenAI) dentro de un async def, en vez del asíncrono (AsyncOpenAI). Funciona, pero congela el servidor mientras el modelo "piensa".

En la industria

Streaming de tokens

Los usuarios de ChatGPT esperan ver las palabras aparecer de a una. Eso se logra con generadores asíncronos.

sin streaming

El servidor espera los 500 tokens completos y recién ahí los manda. El usuario mira una pantalla vacía.

con streaming

Cada token se envía al frontend apenas llega de la red. El usuario empieza a leer casi al instante.

LLMgenera token a token
→
Tu servidorasync for token in stream
→
Frontendpor SSE o WebSockets

TTFT (Time To First Token): cuánto tarda en aparecer la primera palabra. Es una de las métricas de experiencia de usuario más importantes en productos de IA. SSE y WebSockets son dos formas de que el servidor le mande datos al navegador de a poco.

Ejemplo resuelto

Juntamos todo: embeddings en lote

El caso: generar los embeddings de 8 textos de forma concurrente, con tres condiciones.

🚪 Límite

Como máximo 3 llamadas a la vez.
Semaphore(3)

⏱️ Timeout

Cada llamada tiene 2 segundos.
asyncio.timeout(2.0)

🛡️ Sin caídas

Un fallo no tumba el lote.
return_exceptions=True

8 textos
→
gathercrea las 8 tareas
→
Semáforopasan de a 3
→
Timeout2 s por llamada
→
Resultadosok o fallido, nunca un crash

El código corre tal cual, sin API keys: la latencia de red se simula con asyncio.sleep y un tiempo al azar entre 0,5 y 2,5 segundos.

Ejemplo resuelto: código completo y comentado

Código completo · copiá, pegá y corré · no necesita instalar nada 
# =====================================================================
# EJEMPLO RESUELTO: embeddings en lote con control de concurrencia
# =====================================================================
# Junta las tres piezas de la clase: gather, Semaphore y timeout.
# No llama a ninguna API: simula la espera de red, así corre sin keys.
# =====================================================================
import asyncio
import random   # para inventar una latencia distinta en cada llamada
import time     # solo para medir cuánto tardó todo


# ---------------------------------------------------------------------
# 1. Una "llamada a la API de embeddings" simulada (tarea I/O-bound)
# ---------------------------------------------------------------------
async def get_embedding(text: str, sem: asyncio.Semaphore) -> dict:

    # El semáforo es el "portero": si ya hay 3 llamadas adentro,
    # esta espera acá hasta que salga alguna.
    async with sem:
        # Latencia de red simulada: entre 0.5 y 2.5 segundos
        latency = random.uniform(0.5, 2.5)
        try:
            # Si lo de adentro tarda más de 2 s, se cancela y lanza TimeoutError
            async with asyncio.timeout(2.0):
                # await asyncio.sleep: espera SIN bloquear el event loop.
                # Con time.sleep se frenarían todas las demás tareas.
                await asyncio.sleep(latency)
                return {"text": text, "dim": 1536, "ok": True}
        except TimeoutError:
            # En vez de romper el programa, devolvemos un resultado
            # marcado como fallido.
            return {"text": text, "ok": False, "error": "timeout"}


# ---------------------------------------------------------------------
# 2. El orquestador: dispara todas las tareas de forma concurrente
# ---------------------------------------------------------------------
async def embed_batch(texts: list[str]) -> list[dict]:
    # Un solo semáforo, compartido por todas las llamadas: máximo 3 a la vez
    sem = asyncio.Semaphore(3)

    # Una corrutina por texto. Todavía no se ejecuta ninguna.
    tasks = [get_embedding(t, sem) for t in texts]

    # gather las dispara todas y espera a que terminen.
    # El * "desarma" la lista: es como escribir gather(t1, t2, t3, ...).
    # return_exceptions=True: si una falla con un error inesperado,
    # ese error vuelve como un resultado más y el lote no se cae.
    return await asyncio.gather(*tasks, return_exceptions=True)


# ---------------------------------------------------------------------
# 3. Punto de entrada
# ---------------------------------------------------------------------
async def main():
    # 8 textos de prueba: "documento_0" ... "documento_7"
    textos = [f"documento_{i}" for i in range(8)]

    inicio = time.perf_counter()              # arrancamos el cronómetro
    resultados = await embed_batch(textos)
    elapsed = time.perf_counter() - inicio    # segundos que tardó todo

    # Separamos los que salieron bien de los que fallaron.
    # isinstance(r, dict) descarta posibles excepciones devueltas por gather.
    ok = [r for r in resultados if isinstance(r, dict) and r.get("ok")]
    fallidos = [r for r in resultados if isinstance(r, dict) and not r.get("ok")]

    print(f"Procesados OK: {len(ok)}/{len(textos)} en {elapsed:.2f}s")
    for f in fallidos:
        print(f"  Falló: {f['text']} -> {f['error']}")


if __name__ == "__main__":
    asyncio.run(main())   # único punto de entrada

Ejemplo resuelto: qué deberías ver

Procesados OK: 6/8 en 4.61s
  Falló: documento_2 -> timeout
  Falló: documento_5 -> timeout

Salida aproximada: cambia en cada corrida porque la latencia es aleatoria.

PiezaQué hace acá
Semaphore(3)Aunque se crean 8 tareas, solo 3 están dentro del bloque a la vez. Por eso se procesan en unas 3 "tandas", no todas de golpe.
gather(*tasks, ...)Dispara las 8 y espera a todas. Con return_exceptions=True, un error vuelve como un resultado más.
timeout(2.0)Si la latencia simulada pasa de 2 s, lanza TimeoutError; lo capturamos y devolvemos un resultado marcado como fallido.
await asyncio.sleepSimula la red sin bloquear el loop. Con time.sleep se habrían procesado de a una.

Para pensar: si tuvieras que embeddear 10.000 filas, ¿harías gather con las 10.000 a la vez? No: te ganarías un 429. Las encolás todas, y el semáforo asegura que solo N corran en simultáneo. Es exactamente este patrón.

Buenas prácticas de asyncio

  • asyncio.run() como único punto de entrada de tus scripts.
  • Si necesitás el loop desde adentro de una función, asyncio.get_running_loop() en vez de la versión antigua.
  • Nunca bloquees el loop: las funciones síncronas de I/O van envueltas en asyncio.to_thread().
  • Timeouts y semáforos desde el día 1: un sistema de IA sin control de flujo termina agotando cuotas y con latencias extremas.
  • asyncio.TaskGroup para grupos de tareas que dependen entre sí.
# TaskGroup (Python 3.11+): si una tarea falla, cancela las demás limpiamente
async with asyncio.TaskGroup() as tg:
    t1 = tg.create_task(buscar_documentos(pregunta))
    t2 = tg.create_task(buscar_en_web(pregunta))
# Al salir del bloque, las dos terminaron
docs, web = t1.result(), t2.result()

gather(return_exceptions=True)las demás siguen; el error vuelve en la listacada resultado sirve por separado (un lote)

Abstracción de clientes

La capa de conexión: ¿por qué abstraer?

Un error muy común es crear el cliente de OpenAI o Anthropic directamente en la lógica de negocio. Eso trae tres problemas:

acoplamiento

Cambiar de un modelo de OpenAI a uno de Anthropic obliga a reescribir decenas de líneas.

testing difícil

Cuesta simular (mockear) la API si el cliente está "enterrado" en el código.

inconsistencia

Cada SDK devuelve la respuesta con otra forma.

ProveedorCómo se llamaDónde está el texto
OpenAIclient.chat.completions.create(...)response.choices[0].message.content
Anthropicclient.messages.create(...)response.content[0].text (content es una lista)

Abstraer = esconder esas diferencias detrás de una interfaz común. Como un adaptador de enchufe: el resto de tu app siempre enchufa igual.

🏭 Patrón Factory

Una "fábrica" que decide qué cliente crear en tiempo de ejecución, según la configuración. Tu app pide "un cliente" y no le importa cuál le toca.

🔑 SecretStr de Pydantic

Un tipo para guardar claves. Si se imprime o aparece en un log de error, muestra ********** en vez de la clave real.

key = SecretStr("sk-abc123")
print(key)                     # **********   (seguro para logs)
print(key.get_secret_value())  # sk-abc123    (solo cuando hace falta de verdad)

Las dos clases heredan de BaseLLMClient, una clase abstracta: un "contrato" que obliga a que todas tengan el método chat().

Ejercicio: solución completa y comentada

Código completo · corre con keys de prueba, sin gastar créditos 
# =====================================================================
# EJERCICIO: una capa para cambiar de proveedor de LLM sin tocar la app
# =====================================================================
# Antes de correrlo (una sola vez), en la terminal:
#     pip install openai anthropic pydantic
# =====================================================================
import asyncio
from abc import ABC, abstractmethod   # para definir la clase "contrato"
from enum import Enum                 # para una lista cerrada de opciones
from pydantic import BaseModel, SecretStr

# TODO 1: los clientes ASÍNCRONOS de cada SDK (no OpenAI ni Anthropic a secas:
# esos son síncronos y bloquearían el event loop)
from openai import AsyncOpenAI
from anthropic import AsyncAnthropic


# Los proveedores posibles. Un Enum evita errores de tipeo como "opnai".
class Provider(str, Enum):
    OPENAI = "openai"
    ANTHROPIC = "anthropic"


# ---------------------------------------------------------------------
# TODO 2: la configuración, validada con Pydantic
# ---------------------------------------------------------------------
class LLMConfig(BaseModel):
    # SecretStr: la clave no se muestra al imprimir ni en los logs.
    # "| None = None": el campo es opcional (podés tener una sola key).
    openai_api_key: SecretStr | None = None
    anthropic_api_key: SecretStr | None = None


# ---------------------------------------------------------------------
# El contrato: toda clase cliente DEBE tener un método chat()
# ---------------------------------------------------------------------
class BaseLLMClient(ABC):
    @abstractmethod
    async def chat(self, prompt: str) -> str:
        pass


# ---------------------------------------------------------------------
# TODO 3: un cliente por proveedor. Los dos devuelven SOLO el texto.
# ---------------------------------------------------------------------
class OpenAIClient(BaseLLMClient):
    def __init__(self, api_key: SecretStr, model: str = "gpt-4o"):
        # get_secret_value() "destapa" la clave: solo acá, donde hace falta
        self.client = AsyncOpenAI(api_key=api_key.get_secret_value())
        self.model = model

    async def chat(self, prompt: str) -> str:
        response = await self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "user", "content": prompt}])
        # En OpenAI el texto está en choices[0].message.content
        return response.choices[0].message.content


class AnthropicClient(BaseLLMClient):
    # Ajustá "model" al que tengas disponible en tu cuenta
    def __init__(self, api_key: SecretStr, model: str = "claude-sonnet-4-5"):
        self.client = AsyncAnthropic(api_key=api_key.get_secret_value())
        self.model = model

    async def chat(self, prompt: str) -> str:
        response = await self.client.messages.create(
            model=self.model,
            max_tokens=1024,   # en Anthropic este parámetro es obligatorio
            messages=[{"role": "user", "content": prompt}])
        # En Anthropic, content es una LISTA de bloques: el texto está en el primero
        return response.content[0].text


# ---------------------------------------------------------------------
# TODO 4: la fábrica. Decide qué cliente crear según el proveedor.
# ---------------------------------------------------------------------
class LLMFactory:
    @staticmethod   # se llama sin crear un objeto: LLMFactory.create_client(...)
    def create_client(provider: Provider, config: LLMConfig) -> BaseLLMClient:

        if provider == Provider.OPENAI:
            # Validamos nosotros: un error claro y temprano, no uno del SDK
            if config.openai_api_key is None:
                raise ValueError("Falta la API key de OpenAI (openai_api_key)")
            return OpenAIClient(config.openai_api_key)

        if provider == Provider.ANTHROPIC:
            if config.anthropic_api_key is None:
                raise ValueError("Falta la API key de Anthropic (anthropic_api_key)")
            return AnthropicClient(config.anthropic_api_key)

        raise ValueError(f"Proveedor no soportado: {provider}")


# ---------------------------------------------------------------------
# TODO 5: programa principal
# ---------------------------------------------------------------------
async def main():
    # Key de prueba: alcanza para CREAR el cliente sin gastar créditos.
    # A propósito, no cargamos la de Anthropic.
    config = LLMConfig(openai_api_key=SecretStr("sk-dummy"))
    print("Configuración:", config)   # la clave sale tapada con asteriscos

    # Pedimos un cliente a la fábrica
    client = LLMFactory.create_client(Provider.OPENAI, config)
    print("Cliente creado:", type(client).__name__)

    # Con una key real, usarlo es igual para cualquier proveedor:
    #     respuesta = await client.chat("¿Qué es la entropía?")

    # Pedir Anthropic sin su key: tiene que saltar NUESTRO ValueError
    try:
        LLMFactory.create_client(Provider.ANTHROPIC, config)
    except ValueError as e:
        print("Error controlado:", e)


if __name__ == "__main__":
    asyncio.run(main())

Resumen de la clase

  • En IA el tiempo se va en esperar: asyncio aprovecha esas esperas (I/O-bound), no acelera cálculos (CPU-bound).
  • Corrutina (async def / await): función que puede pausarse. Event loop: quien coordina. Task: corrutina ya en marcha.
  • asyncio.run() como único punto de entrada; gather para esperar varias llamadas a la vez.
  • Timeouts contra la espera infinita y semáforos contra el 429.
  • Nunca bloquees el loop: await asyncio.sleep, clientes async y to_thread() para lo síncrono.
  • Streaming: mandar cada token apenas llega baja el TTFT.
  • Factory + interfaz común: cambiar de proveedor sin tocar la app; SecretStr para que las claves no aparezcan en los logs.

# Streaming: un generador asíncrono usa yield dentro de un async for
async def stream(self, prompt: str):
    stream = await self.client.chat.completions.create(
        model=self.model, messages=[{"role": "user", "content": prompt}], stream=True)
    async for chunk in stream:                          # cada fragmento, apenas llega
        if chunk.choices and chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content          # lo entrega sin esperar al resto
